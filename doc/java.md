## Bindings

The following snippet illustrates the creation of an `RGBADescriptor` using the library:

    import com.sandflow.smpte.mxf.types.RGBADescriptor;
    ...
    RGBADescriptor d = new RGBADescriptor();
    d.InstanceID = UUID.fromRandom();
    d.SampleRate = sampleRate;
    d.FrameLayout = LayoutType.FullFrame;
    d.StoredWidth = 640L;
    d.StoredHeight = 360L;
    d.DisplayF2Offset = 0;
    d.ImageAspectRatio = Fraction.of(640, 360);
    d.TransferCharacteristic = Labels.TransferCharacteristic_ITU709.asUL();
    d.PictureCompression = Labels.JPEG2000BroadcastContributionSingleTileProfileLevel5;
    d.ColorPrimaries = Labels.ColorPrimaries_ITU709.asUL();
    d.VideoLineMap = new Int32Array();
    d.VideoLineMap.add(0);
    d.VideoLineMap.add(0);
    d.ComponentMaxRef = 65535L;
    d.ComponentMinRef = 0L;
    d.ScanningDirection = ScanningDirectionType.ScanningDirection_LeftToRightTopToBottom;
    d.PixelLayout = new RGBALayout();
    d.PixelLayout.add(new RGBAComponent(RGBAComponentKind.CompRed, (short) 16));
    ...


## Testing

Both the Java and C++ implementations are tested using the same [test resources](./test-resources).

In addition to unit tests, the library also defines basic compatibility tests at [compat.sh](./java-library/src/test/sh/compat.sh) against popular MXF libraries (FFMPEG, ASDCP and BMX). A [Dockerfile](./Dockerfile) that sets up the test environment is provided.


### Architecture

At the heart of the RegXML generator is `FragmentBuilder`, which creates an XML fragment from a
KLV Group given a RegXML metadictionary and a collection of KLV Groups from which strong
references are resolved. Its rules engine follows the rules specified in ST 2001-1 as closely as
possible. A sister class, `XMLSchemaBuilder`, creates a matching XML Schema that can be used to
validate RegXML fragments.

Metadictionaries can be imported and exported from XML documents that conform to the schema
specified in SMPTE ST 2001-1. They can also be created from SMPTE Metadata Registers published in
XML form, using `RegisterImporter`.

The C++ implementation under `cpp/` generally follows the architecture and idioms of the Java
implementation: applications typically call `FragmentBuilder::fromTriplet()` or
`MXFFragmentBuilder::fromInputStream()`, as demonstrated at
[MetaDictionaryTest.cpp](cpp/src/test/cpp/com/sandflow/smpte/dict/MetaDictionaryTest.cpp). Unlike
the Java implementation, the C++ implementation does not itself convert SMPTE Metadata Registers
to RegXML metadictionaries -- it relies on metadictionaries generated by the Java implementation's
`XMLRegistersToDict` tool (see below), such as those under
[resources/regxml-dicts](resources/regxml-dicts).
